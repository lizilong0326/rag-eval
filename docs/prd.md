# RAG 回归评测与错误归因系统（PRD）

状态：拟立项，尚未开发。目标岗位：AI 产品经理 / FDE。本文中的指标是验收口径，不是已经取得的结果。

## 为什么值得做

你已经做过经销商知识治理、房车客服与 AI 应用联调，简历中也提到 Evals 和 Bad Case。这个项目把「我会评测」变成面试现场可运行的证据：同一套问题，在知识、检索或提示词变更前后，具体哪些答案进步、退化、引用错误或越权，一眼可见。

## 用户与问题

使用者是维护企业知识问答的产品、实施与研发人员。日常困难不是没有一个综合分，而是一次改动后不知道哪个门店、哪个车型、哪类问题受影响，也很难把错误交给责任人修复。

## 产品边界与首版流程

1. 导入公开或合成的文档、问题、期望要点、禁止断言、适用企业和资料版本；至少准备 20 个覆盖正常、资料不足、旧版、跨企业和冲突场景的样例。
2. 用统一适配器调用一个被测问答接口，保存请求、答案、引用文档 ID、耗时、模型/知识版本；敏感输入先脱敏。
3. 同一题集跑基线版和候选版。规则检查「是否引用存在的来源、来源是否属于当前企业、是否说出禁止断言、是否承认资料不足」；语义评分仅作辅助，人工可复核。
4. 报告按未命中、错引用、过期资料、越权、模型补写、接口失败分组，展示原题、原答、引用证据和回归差异；失败项可导出为复现包。

首版不重做知识库、不宣称自动评分等于事实正确，也不接入真实客户资料。先支持一个 HTTP 被测接口和本地演示数据，后续再扩 RAGFlow 等平台适配器。

## 开源借力与独立贡献

用 promptfoo 承接题集执行与断言，用 RAGFlow 或自建 mock 接口作为可选被测系统。自己重点实现企业/版本维度的数据模型、引用核验、Bad Case 分类、人工复核及两版差异报告。采用适配器集成，二开前按锁定版本核对许可证与依赖。

## 验收与交付

- 一个命令可启动演示；同一题集重复运行并输出机器可读报告与可阅读页面。
- 人为注入「跨企业引用、过期政策、无来源补写、接口超时」四类错误，报告能定位到具体题目和证据。
- 人工标注与自动结果分开显示，能回放评分依据；不以单个总分掩盖高风险错误。
- README 写明评测数据来源、适用范围、误判边界、运行成本和上游组件；录屏展示一次真实回归。

## 实施顺序

先定题集 schema 与证据字段，再做接口适配和规则检查，随后做报告 UI 与人工复核，最后接持续集成并用固定失败样例验证。简历可展示「搭建可复跑的 RAG 回归评测与错误归因流程」；准确率、效率提升须完成实测后再写。

## 风险与待确认

答案语义可能正确但措辞不同，故自动评分需抽样复核；引用 ID 若被测接口不返回，只能标注「无法核验」，不能算通过。需确认第一版面向房车客服问答还是通用企业知识问答，以及公开演示资料的授权边界。

## 已确认决策（V2，替代上述待确认项）

1. 产品做成标准：人为注入「跨企业引用、过期政策、无来源补写、接口超时」四类错误后，报告 100% 定位到具体题目与证据；同一题集重复运行产出结果一致（除耗时字段）；规则检查经人工抽样核对一致率不低于 90%。
2. 使用者为维护企业知识问答的产品、实施与研发人员；使用频率为每次知识或提示词变更时跑批（周级）；首版以 CLI 同步执行，跑完产读报告文件。
3. 第一版面向通用企业知识问答引擎，用房车客服场景作为演示数据；被测接口契约为 HTTP POST，返回 JSON：`{answer, citations: [{doc_id, enterprise_id, version}], model_version, knowledge_version, latency_ms}`；引用文档 ID 允许缺失。
4. 外部依赖仅三个：promptfoo（本地）、被测 HTTP 接口（自建 mock 优先，RAGFlow 可选）、语义评分模型（DeepSeek）。
5. 领域知识存本地 YAML 文件。题集 schema 字段：`id, question, expected_points[], forbidden_claims[], enterprise_id, version, scenario`。企业/版本数据模型字段：`enterprise_id, version, valid_from, valid_to`。
6. 公开演示资料授权边界：全部使用合成数据与公开文档（标注来源），不出现真实客户、门店或人员信息，录屏只展示合成数据。
7. 容错与降级：被测接口调用超时阈值 5 秒（可配置）；仅对超时与 5xx 重试 1 次；4xx、连接拒绝、返回体结构异常不重试，直接归入「接口失败」分组。引用文档 ID 缺失时标记「无法核验」、不计为通过、单列统计。
8. 可量化验收指标：四类错误定位率 100%；同题集两次运行结果一致（除耗时）；规则检查经人工抽样核对一致率 ≥ 90%。准确率与效率提升属待实测项，只在 README 说明，不作验收口径。
9. 性能与成本约束：单次运行（20 题）不超过 10 分钟；并发为 1（首版串行，避免压测被测接口）；语义评分用 DeepSeek，20 题单次成本约不超过 1 元。
10. 实现语言与运行环境：Python 3.12，本地单进程 CLI。
11. 语义评分辅助模型：DeepSeek deepseek-chat。
12. 首版不需要上下文压缩（20 题、日志量小、无长会话）、不需要后台任务（同步跑 ≤10 分钟）、不需要多 Agent 团队（单进程串行、无并行隔离）。
13. 记忆与持久化：首版需要持久化企业/版本数据模型、题库、每次运行结果与报告、人工复核记录、回归差异基线；不做跨会话用户偏好记忆。
14. 人工复核：抽样比例不低于 20%，且每个错误分组至少覆盖 1 题；判定标准为人工核对「引用是否真实存在、来源是否属于当前企业、是否触碰禁止断言」。
15. 测试要求：核心循环（导入→调用→规则检查→报告）有单测；权限与安全有边界测试（未授权地址或凭据拒绝调用）；四类注入错误各至少 1 条固定用例；敏感输入脱敏有单测。
16. 过期资料判定规则：引用文档的 version 不在当前企业 `valid_from ≤ 当前版本 ≤ valid_to` 范围内即判「过期资料」；「当前版本」取自题集条目的 version 字段。
17. 被测接口鉴权：HTTP 请求头 `Authorization: Bearer <token>`；接口地址与凭据均从外置配置读取，地址或凭据不在配置白名单内即拒绝调用，归入「接口失败」分组。
18. 「承认资料不足」判定：命中关键词（无法/暂未/未找到/资料不足/尚无记录等）即判承认，其余情况交语义评分辅助，由人工复核兜底。
19. 可复现性口径：一致性仅对确定性的规则检查结果强制成立；语义评分为辅助参考、允许抖动，其置信度单列展示，不作为复现判据。
20. 权限系统边界：本产品涉及隐私数据处理（问题文本与答案可能含个人信息，必须先脱敏再外发）与敏感的外部系统调用（携带 Bearer 凭据访问被测接口），必须内置权限控制能力——接口地址与凭据白名单校验、未授权调用默认拒绝、拒绝事件记审计日志；权限与安全需有边界测试。
